# my12306 — 12306 自动购票软件（管理台 + 后端服务）

多用户、多计划的 12306 自动订票系统：按「起售时刻」秒级触发抢票，订票成功后**不付款**，通过飞书群机器人通知用户自行登录付款。全 TypeScript 实现（Node.js + Vue 3），无头浏览器操作，不占用本地浏览器。

## 核心特性

1. **多用户**：用户名 + 密码登录，JWT 鉴权，数据按用户隔离。
2. **多购票计划**：每个用户可定义多个计划——
   - 指定乘车人、出发/到达站、时间范围（如 08:00–09:00）；
   - 日期支持「具体日期」或「按工作周期推算」（如每周一 南京→上海，遇节假日/调休自动顺延）；
   - 可指定车次与座位偏好（A 靠窗 / B 中间 / C 过道 / D 过道 / F 靠窗，多选或不指定）；
   - 新建前可「推算日期预览」，顺延的日期会额外标注 ⏩ 及原因。
3. **无头浏览器登录 12306**：每用户独立持久化 user-data-dir；登录采用**扫码登录**（系统全程不接触密码、不需要手机号），二维码通过 WebSocket 实时推送到管理台，用 12306 APP 扫码确认即可；登录态定时保活，失活时飞书告警。管理台登录后若检测到无活跃 12306 会话，会自动弹窗引导登录。
4. **飞书通知**：群机器人 webhook + 签名校验（HMAC-SHA256），支持成功提醒、失活告警、任务失败通知。
5. **到点自动购买**：自动查询车票起售时间，在**起售时刻**触发下单（而非出发前），成功后停在确认页**不进入支付**，飞书提醒用户登录付款。
6. **纯 Web 架构**：后端常驻服务同时托管管理台前端，浏览器访问即可，无需安装桌面客户端。

- **后端**：`server/` — Fastify HTTP API + WebSocket、better-sqlite3 数据层、Playwright 浏览器自动化、任务调度器、飞书通知。
- **前端**：`web/` — Vue 3 + Element Plus，构建产物由后端静态托管（生产模式）。
- **无头浏览器**：macOS 下固定无头（等价 xvfb 效果）；Linux 下若安装了 xvfb 会自动使用，不占用本地桌面浏览器。

## 快速开始

### 环境要求

- Node.js ≥ 18（推荐 22）
- 首次会下载 Playwright 的 Chromium（`npx playwright install chromium`）

### 安装

```bash
npm install                 # 安装 server + web 依赖（workspaces）
npx playwright install chromium
```

### 开发模式（前后端热重载）

```bash
npm run dev:server          # 后端 http://127.0.0.1:7788
npm run dev:web             # 前端 http://localhost:7789（代理 7788）
```

### 生产模式

```bash
npm run build:web           # 构建前端 -> web/dist
npm run build:server        # 构建 + 拷贝 schema.sql -> server/dist
npm run start:server        # 启动后端（同时托管 web/dist）
```

访问 `http://127.0.0.1:7788`，默认管理员账号 **admin / admin123**（登录后请尽快修改）。

### 配置项（环境变量）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MY12306_PORT` / `PORT` | `7788` | 服务端口 |
| `MY12306_HOST` | `127.0.0.1` | 监听地址（外网访问请改为 `0.0.0.0` 并注意安全） |
| `MY12306_DATA_DIR` | `server/data` | 数据目录（数据库 / 浏览器 profile / 会话 / 主密钥） |
| `MY12306_PRESALE_DAYS` | `14` | 12306 预售期兜底值（最终以起售查询接口返回为准） |
| `MY12306_PRE_TRIGGER_MS` | `3000` | 起售时刻前 N 毫秒进入待触发队列 |
| `MY12306_HEADLESS` | `true` | 无头浏览器开关（Linux 有 DISPLAY 时可设 `false` 调试） |

## 使用流程

1. **登录管理台**（默认 admin/admin123），在「用户」页修改密码。
2. **配置飞书**（「飞书」页）：填写群机器人 webhook 地址与签名密钥，可「发送测试消息」验证连通。
3. **登录 12306**（「12306 会话」页）：输入绑定手机号，系统在 12306 登录页填入并触发发送验证码；收到短信后在弹窗中输入验证码（透传给 12306）完成登录。**全程不保存密码**，登录成功后只保存浏览器会话并自动保活，失活时飞书通知重新登录。
4. **添加乘车人**（可在「会话」页从 12306 同步，或手工录入）。
5. **新建购票计划**（「计划」页）：选择乘车人、站点、日期模式、时间范围、车次与座位偏好；保存前点「推算日期预览」确认具体购票日期与顺延标注。
6. **自动执行**：调度器会为每个计划日期查询起售时间，在**起售时刻**自动抢票；下单成功后**不付款**，飞书群收到提醒，用户自行登录 12306 完成支付。

## 关键设计说明

- **按起售时刻触发（非出发时间）**：用户明确强调订票及时性。调度器把每个计划日期换算成「起售时刻」，由秒级触发器在起售瞬间执行抢票，而不是等到出发前。任务状态机：`pending → queried → queued → running → success / failed`，失败带退避重试（默认 3 次）。
- **节假日顺延**：日期引擎使用 holiday-cn 节假日数据；recurring 模式下若推算日是非工作日，自动顺延到下一个工作日，并标注 `postponed` 与原因（如「国庆节，顺延至 2026-10-08」）。
- **验证码透传**：12306 图形验证码截图经 WebSocket 实时推送到管理台，用户在网页上点选，坐标回传给后端继续登录流程；支持滑块兜底。
- **不付款**：自动化只完成到「确认订单」页，订单成功即停止，绝不进入支付环节，避免误扣款。
- **会话保活与失活告警**：每 10 分钟检查 12306 登录态；一旦失活，立即通过飞书通知用户重新登录。
- **不保存 12306 密码**：登录只走「手机号 → 12306 下发短信验证码 → 用户输入验证码透传」的流程，系统全程不接触密码；登录成功后只保存浏览器会话（user-data-dir）并保活。
- **登录引导**：管理台登录后若检测到无活跃 12306 会话，自动弹窗询问是否登录 12306，确认后跳转会话页（本次浏览器会话内只提示一次）。
- **会话保活与失活告警**：每 10 分钟检查 12306 登录态；一旦失活，立即通过飞书通知用户重新登录。
- **数据安全**：旧库启动时会自动删除历史 `password_enc` 密文列。数据目录 `server/data/` 已 gitignore，**请勿提交**。

## 飞书机器人配置

1. 在飞书群添加「自定义机器人」，获得 webhook 地址（`https://open.feishu.cn/open-apis/bot/v2/hook/xxxxx`）。
2. 安全设置开启「签名校验」，获得签名密钥。
3. 在管理台「飞书」页填入两者并保存。本系统按官方算法签名：

   ```
   stringToSign = timestamp + "\n" + secret
   sign = Base64( HMAC-SHA256(stringToSign, key=stringToSign) )
   ```
